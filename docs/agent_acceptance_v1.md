# Roco Agent 第一版范围与验收用例

编制日期：2026-11-02。

## 第一版目标

支持精灵资料查询、技能详情查询、精灵与技能关联查询，以及种族值比较；支持对话中的明确指代与必要澄清。以本地精灵库和技能库提供回答依据。

第一版完成标准：下列 20 条用例全部通过。每条用例同时检查回答内容、数据依据和边界处理。具体措辞可以变化，名称、数字、条件和语义以预期要点为准。

## 数据与验收约定

- 本文数字以编制时的本地快照为基准，代表当前数据源记录。来源更新时，先核对数据变化，再更新对应预期值。
- 精灵数据：`data/pets/<pet_id>/combined.json`。技能数据：`data/skills/<skill_id>.json`。
- 技能学习来源及条件取自精灵的 `sections.skills`；技能效果取自技能库。通过 `skill_id` 关联。
- `level`、`machine`、`blood` 分别表示升级技能、技能石技能、血脉技能。
- 回答显示精灵或技能名称，正文聚焦玩家问题。来源、更新时间和缓存信息保留在程序侧核验记录中，发给模型的工具结果提供游戏资料与查询状态。
- 单轮用例使用新会话；多轮用例仅使用该用例列出的对话历史。
- “上下文缺失”“记录不存在”“详情缺失”“空列表”“旧缓存”使用各自的明确状态表达。
- 工具名称、调用次数和执行顺序允许随实现调整；验收以数据使用和最终行为为准。
- 此表是待执行的验收标准。当前已核对本地预期数据，Agent 的执行结果在实现后填写。

## A. 精灵资料查询

### R01：基础档案

- **用户问题**：喵喵是什么属性？它的 ID 和图鉴编号分别是多少？
- **需要的数据**：3001 的 `sections.base`、`sections.profile`。
- **预期要点**：名称喵喵，草属性，`pet_id=3001`，图鉴编号 `002`。
- **通过条件**：明确区分精灵 ID 与图鉴编号，保留编号的前导零。

### R02：种族值

- **用户问题**：喵喵六项种族值是多少，总和多少？
- **需要的数据**：3001 的 `sections.profile.attributes`。
- **预期要点**：生命 65、物攻 66、物防 49、魔攻 66、魔防 91、速度 33，总和 370。
- **通过条件**：六项对应关系及总和全部正确，并标明这些数值属于种族值。

### R03：特性

- **用户问题**：喵喵的特性是什么，什么时候生效？
- **需要的数据**：3001 的 `sections.features.items`。
- **预期要点**：氧循环；使用草系技能后，回复 10% 生命。
- **通过条件**：名称、触发条件及回复比例准确。

### R04：进化条件

- **用户问题**：喵喵进化到喵呜，再到魔力猫，分别要什么条件？
- **需要的数据**：3001 的 `sections.family.members`。
- **预期要点**：喵呜（3025）要求 16 级、魔法粉尘 5、向阳花 2、费用 10000；魔力猫（3007）要求 32 级、草系灵石 5、费用 30000。
- **通过条件**：按前后阶段分别列出等级、材料、数量和费用，按来源名称表达材料；费用字段按来源的数值呈现。

### R05：获取方式

- **用户问题**：喵喵可以怎么获得？
- **需要的数据**：3001 的 `sections.acquisition`。
- **预期要点**：地图出没、精灵蛋孵化、果实刷新；地图示例可以取轻风山、月牙湖岸。
- **通过条件**：覆盖三类方式，地图名称与来源一致。以当前收录资料的范围说明获取途径。

### R06：孵化时间与蛋组

- **用户问题**：喵喵的蛋多久孵化，属于哪些蛋组？
- **需要的数据**：3001 的 `sections.egg.hatch_seconds`、`sections.profile.egg_groups`。
- **预期要点**：43200 秒，即 12 小时；动物组、拟人组。
- **通过条件**：时间换算正确，两个蛋组均列出。

## B. 技能与关联查询

### R07：独立技能详情

- **用户问题**：抓挠的属性、威力、能耗和效果是什么？
- **需要的数据**：技能 7020360 的 `data`。
- **预期要点**：普通属性、物攻技能、威力 35、能耗 0；造成物理伤害，自己回复 1 能量。
- **通过条件**：按技能名定位到正确 ID，完整回答四项信息，能耗 0 被正确保留。

### R08：升级技能表

- **用户问题**：列出喵喵所有升级技能和学习等级。
- **需要的数据**：3001 的 `sections.skills.level`，关联各技能 ID 的技能库名称。
- **预期要点**：共 16 条，按等级升序排列；例如 1 级抓挠（7020360）、1 级休息回复（7020640）、6 级棘突（7030440）。完整 ID 和等级集合以该分组为准。
- **通过条件**：16 条与来源逐项对应，每条包括名称和学习等级；技能石、血脉技能按各自来源处理。

### R09：技能石关联

- **用户问题**：喵喵能学毒沼吗？通过什么方式？技能效果是什么？
- **需要的数据**：3001 的 `sections.skills.machine`，技能 7120200 的 `data`。
- **预期要点**：能，通过技能石；毒属性、物攻技能、威力 80、能耗 2，造成物理伤害。
- **通过条件**：用精灵关联确认学习资格，用技能库回答详情；学习方式明确为技能石。

### R10：血脉关联条件

- **用户问题**：喵喵能学星星撞击吗？有什么学习条件？
- **需要的数据**：3001 的 `sections.skills.blood`，技能 7020910 的 `data`；血脉显示名称可查原始来源响应。
- **预期要点**：血脉技能，记录的学习等级为 15，`bloodline_id=1`；技能名称为星星撞击。原始响应中对应普通系血脉。
- **通过条件**：同时保留血脉来源、等级和血脉限定。显示血脉名称时具备名称映射依据；映射缺失时明确显示血脉 ID。

## C. 比较与条件查询

### R11：两只精灵比较

- **用户问题**：喵喵和迪莫谁的速度种族值高，高多少？
- **需要的数据**：3001、3004 的 `sections.profile.attributes.speed`。
- **预期要点**：喵喵 33，迪莫 92；迪莫高 59。
- **通过条件**：比较对象、数值和差值正确，结论限定在速度种族值。

### R12：排序

- **用户问题**：把喵喵、水蓝蓝、火花、迪莫按速度种族值从高到低排序。
- **需要的数据**：3001～3004 的速度种族值。
- **预期要点**：迪莫 92 > 火花 78 > 水蓝蓝 51 > 喵喵 33。
- **通过条件**：四只精灵排序和数值全部正确。

### R13：条件过滤

- **用户问题**：喵喵在 10 级及以前能学到哪些升级技能？
- **需要的数据**：3001 的 `sections.skills.level`，关联技能名称。
- **预期要点**：共 6 条：抓挠（1）、休息回复（1）、棘突（6）、扫尾（7）、藤绞（8）、防御（10）。
- **通过条件**：包含等级等于 10 的技能，输出集合和等级准确。

## D. 对话理解

### R14：有明确先行对象的追问

- **对话**：用户先问“喵喵是什么属性？”，助手按来源回答后，用户再问“它的特性呢？”
- **需要的数据**：当前对话历史及 3001 的特性资料。
- **预期要点**：识别“它”为喵喵，回答氧循环及其效果。
- **通过条件**：沿用明确对象，完成特性查询。

### R15：缺少先行对象的追问

- **用户问题**：新会话中直接问“它怎么进化？”
- **需要的数据**：当前会话上下文。
- **预期要点**：询问玩家指的是哪只精灵，例如“你想查询哪只精灵的进化条件？”
- **通过条件**：先澄清对象，待玩家提供名称或 ID 后进入查询。

## E. 数据边界与降级

### R16：名称检索为空

- **用户问题**：测试精灵不存在XYZ的特性是什么？
- **前置条件**：使用测试索引，使名称搜索返回空结果，稳定复现检索为空的情况。
- **需要的数据**：名称搜索结果。
- **预期要点**：说明当前资料库未检索到该名称，请玩家确认名称或提供 ID。
- **通过条件**：将结论限定为资料库检索结果，提供下一步查询方式。

### R17：精灵关联存在，技能详情缺失

- **用户问题**：喵喵能学毒沼吗？它的威力是多少？
- **前置条件**：在测试数据副本中保留 3001 的技能石关联，令技能 7120200 的详情查询返回缺失状态。
- **需要的数据**：精灵技能关联与技能库查询状态。
- **预期要点**：确认可通过技能石学习该技能；说明威力详情待补齐。
- **通过条件**：分别表达学习资格已知、技能详情缺失。回答依据为精简精灵关联及独立技能库，体现新的数据分离方式。

### R18：故事列表为空

- **用户问题**：给我讲讲喵喵图鉴里的背景故事。
- **需要的数据**：3001 的 `sections.stories`。
- **预期要点**：当前来源返回 0 条背景故事；可提供图鉴描述，并明确标为图鉴描述。
- **通过条件**：区分接口成功返回空列表与采集失败，准确标注可提供内容的类别。

### R19：后台缓存信息隔离

- **用户问题**：喵喵的特性是什么？
- **前置条件**：使用已有聚合响应的缓存状态，或在测试副本中设置 `stale=true`、`updated_at=2026-11-01T10:22:57+08:00`。
- **需要的数据**：3001 的 `sections.features`；原始响应与缓存标记供程序侧检查。
- **预期要点**：回答氧循环及“使用草系技能后，回复 10% 生命”的效果。
- **通过条件**：模型收到的工具结果包含游戏资料，来源、更新时间、缓存及文件路径等字段留在程序侧；正文聚焦所问特性。

### R20：伤害计算的输入与验证状态

- **用户问题**：用喵喵的种族值算一下抓挠打迪莫的准确伤害。
- **需要的数据**：`data/mechanics/damage_formula.json` 的验证状态；实际攻防能力值所需输入。
- **预期要点**：说明现有公式为社区候选规则，状态为待实测验证；准确计算还需等级、实际物攻物防、强化和减伤等战斗条件。可说明现有数据已知部分，并询问必要条件。
- **通过条件**：明确种族值与实际能力值的区别，准确表达规则验证状态；后续估算以补齐条件和明确假设为前提。
